# 架构研究与独立实现说明

本仓库创建前对两个本地即时通讯项目进行了结构研究，重点比较了：

- 前后端工程化、WebSocket、缓存、异步队列和容器部署；
- 联系人申请、会话、群成员、消息类型和后台治理等领域完整度。

LinkNest IM 没有复制参考仓库的源文件、命名、页面或数据库定义。研究结论被重新组织为以下独立决策：

1. 个人项目从模块化单体开始，只将异步 Worker 分进程。
2. 使用统一会话模型，避免单聊和群聊维护两套消息表及服务。
3. MySQL 作为事实源，Redis 仅保存可重建数据。
4. 用事务 Outbox 解决数据库提交与消息发布的一致性窗口。
5. 用成员级已读游标降低群聊回执写放大。
6. 通过 ADR、接口契约、迁移和分阶段 TODO 保留真实设计过程。

上传 GitHub 前应继续保留自己的提交过程、测试结果和设计取舍，不应把未完成的 TODO 描述成已上线能力。
